# Entity router

`http/entity-router.ts` exposes `makeEntityRouter` — the US-edition of the
BE's entity CRUD factory. Feed it a service implementing
`EntityServiceLike` and it emits governed `RpcRoute[]` carrying the
factory brand `createMicroservice` requires: the same route table, the
same mandatory chain (auth → RBAC → validation → **one** service call →
RFC 7807), zero boilerplate per entity.

## The 12 actions — declared by permissions

A route exists **iff** its permission is declared — the permission IS the
registration, exactly like the BE:

| Action | Route | Service call |
|---|---|---|
| `meta` | `GET /meta` | assembled meta + derived `actions` |
| `list` | `GET /list` | `service.list(query)` |
| `export` | `GET /export` | `streamEntityExport` — meta-derived (requires `meta`; see below) |
| `create` | `POST /` | `service.create(entity)` → 201 |
| `duplicate` | `POST /duplicate` | `service.duplicate(uuids)` — ON by default (pass `duplicate: false` to disable) |
| `bulkDelete` | `POST /bulk-delete` | `service.bulkDelete(items)` |
| `bulkRestore` | `POST /bulk-restore` | `service.bulkRestore(items)` |
| `get` | `GET /:uuid` | `service.get(uuid)` |
| `update` | `PUT /:uuid` | `service.update(uuid, entity)` |
| `delete` | `DELETE /:uuid` | `service.delete(uuid, ?version)` |
| `purge` | `DELETE /:uuid/purge` | `service.purge(uuid, ?version)` |
| `restore` | `POST /:uuid/restore` | `service.restore(uuid, ?version)` |
| `audit` | `GET /:uuid/audit` | `service.audit(uuid, page, limit)` |

`meta.actions` is **derived** from the registered ops using the canonical
vocabulary (`list`, `create.single`, `update.single`, `delete.single`,
`purge.single`, `restore.single`, `read.audit`, `export`, `delete.bulk`,
`restore.bulk`, `duplicate.bulk`) — the FE reads the same op names it gets
from the BE; ops not registered appear `enabled: false`.

## The contract

```ts
makeEntityRouter({
  entityName: "ai_model",            // → /api/v1/entities/ai_model/*
  service: aiModelService,           // EntityServiceLike — structural (dal-pg satisfies it)
  permissions: { list: [...], get: [...], create: [...], ... },
  meta: { ... },                     // static meta → GET /meta (+ actions derived)
  auditable: true,                   // drives meta.collaboration.enabled
  schemas: { createBody, updateBody, listQuery, auditQuery, duplicateBody },
  export: { dictResolver, templates }, // GET /export — only when permissions.export
  guards: { delete: mfaGuard },      // async hook before the service call
})
```

### `export` — meta-derived, first-class op

`permissions.export` + `meta` register `GET /export?file_type=csv|xlsx|pdf|html`.
The handler streams via `streamEntityExport`: columns are **derived from
`meta.columns`** (field types from `type`, `datetime_iana_toggle` → date +
timezone pair; `version`/audit fields never exported), labels resolved
through `EntityExportConfig.dictResolver` — the service wires its own
module-namespaced `TranslationsService` there (e.g. crm → `crm.translations`).
Rows come from `service.stream(query)` — the same filter builder as `list`.
Templates resolve by convention at `templates/<entity>_export_template.{xlsx,html}`;
`EntityExportConfig` can override `columns`, `templates`, `entityLabels`.
Declaring `permissions.export` without `meta` throws at router construction —
export columns cannot exist without meta.

`EntityServiceLike` is a structural interface — the SDK cannot import
`@primebrick/dal-pg` (dependency direction is dal → sdk), so dal-pg's
`makeEntityService` output satisfies it without any coupling.

## Deliberate differences from the BE edition

- **Plain validators** — schemas are `(raw) => T` functions; the SDK is
  zod-free, the service injects `schema.parse` bound to its own validator.
- **`{entity}`-only writes** — the BE's `{entity, translations}` envelope
  becomes `{entity}`: translation piggyback writes are gateway-owned
  (translations live in the BE's system schema). A US entity route MUST
  NOT accept a `translations` key — write schemas should `.strict()`.
- **`guards` replaces Express middlewares** — per-action async hooks
  inside the mandatory chain (the MFA step-up consume is the canonical
  use).
- **No write-tx orchestration** — with no translations piggyback, writes
  are single-call.
- **Bracket-notation queries** — `parseBracketQuery` turns
  `filters[0][field]=x&filters[0][op]=%3D` into structured objects, the
  same surface the FE produces against the BE.
